## Project structure

```text
public/
  assets/              # supplied assets (ships, tiles, effects, ui_sheet*.json)
    sounds/            # WAV files
  mockServiceWorker.js # generated by MSW (required in published build)
src/
  app/                 # App.tsx, providers (QueryClient), screen flow state
  config/              # typed gameConfig.ts, option limits and validation
  storage/             # local persistence (options, pending queue, mock database)
  api/                 # typed contracts, Axios client
    queries/           # TanStack Query hooks (ranking, history, registration)
  game/
    core/              # GameLoop (fixed timestep), Clock, seeded RNG, World
    entities/          # Player, Chaser, Shooter, Projectile, Island (data-only)
    systems/           # movement, collision, weapons/cooldown, spawn, damage, match rules
    input/             # keyboard + touch -> InputState
    render/            # PixiJS layer: views, health bars, effects, resize
    assets/            # manifest, load flow, progress, failure handling
    bridge/            # external store bindings game -> React, no frame-by-frame React re-renders
  ui/
    screens/           # Menu, Options, Match, Result
    components/        # buttons, tabs, dialogs, pagination, empty/error states
    hud/               # semantic HUD (health, score, timer), pause overlay, touch controls
    styles/
  mocks/               # MSW: handlers, in-memory db + localStorage
    fixtures/          # shared data for dev, tests, and demo
    scenarios/         # network scenarios (success, empty, slow, timeout, 5xx)
  testing/             # instrumentation (window.__PIRATE__): observe state, control clock/seed
tests/
  e2e/                 # Playwright E2E
  visual/              # visual regression checks
  fixtures/            # Playwright fixtures
docs/
  perf/                # profiling evidence
```

## Architecture principles

- Pure TypeScript simulation with no PixiJS dependency for gameplay logic
- Fixed-timestep game loop (example: 1/60 s) + accumulator; clamp large delta to avoid teleporting after stalls
- React does not re-render every frame; HUD reads from an external store that only emits when values change
- Clean teardown in `useEffect` (ticker, listeners, timers, `app.destroy`) for safe Strict Mode behavior
- All balance constants live in `src/config/gameConfig.ts`
- Gameplay input is captured only while gameplay is active
- API failures never block gameplay

## Phases

### Day 1

#### 1. Project setup

- Vite + React + TypeScript strict
- PixiJS v8, ESLint, Prettier, Vitest, Playwright, MSW (`mockServiceWorker.js` under `public/`)
- Scripts: `dev`, `build`, `preview`, `lint`, `typecheck`, `test`, `test:e2e`
- Copy assets into `public/assets` (ship atlas converted to JSON)
- `ASSETS.md` documenting asset origin and approved usage

#### 2. Fixed timestep & input loop

- Fixed-step loop with accumulator and clamped delta
- Keyboard input via `event.code`; only captured during active gameplay
- Resolution of input merge: keyboard + touch
- Movement with inertia, rotation, and arena bounds
- Pixi runtime mounted via React with safe cleanup under Strict Mode
- Asset loading with progress, accessible error UI and retry flow
- Persistent world per match with letterboxing on resize
- Tests: 14 unit + 2 E2E (asset failure/retry and 5 cycles without leaking canvas)

#### 3. Collisions

- Arena bounds using full hull and orientation
- 3 islands in a fixed proportional layout; collision via union of circles
- Hull modeled as 3 circles (bow, center, stern) with coast sliding behavior
- `separateShips` prepared for enemy interactions
- Debug visualization via `?colliders` parameter
- Projectile vs island collisions (phase 4)

#### 4. Combat

- Front shot (1 projectile) and side shot (3 spread shots per side)
- Auto-fire while holding trigger
- Weapon cooldowns handled independently per side
- Projectile lifetime, damage, and one-time hit application
- Projectile removal when leaving arena or after expiration
- Damage state + red flash on hull hit
- 11 unit tests for weapons/projectiles, including cadence consistency at 30 and 144 fps

#### 5. Enemies

- Chaser: hunts player, explodes on impact with 25 damage, no score on self-destruction
- Shooter: approaches to about 80% of range, aims, fires when line of sight is clear
- Island avoidance via “whiskers” (probes ahead and to the sides)
- Spawner with configurable interval, one spawn window at a time, 60/40 Chaser/Shooter mix with seeded randomness
- Max 10 active enemies; spawn waits for free space
- Reproducible runs via `?seed=` parameter
- Sunk enemy removed immediately; wreck sinks + explosion + sound
- HP bars above ships with redraw only when HP changes and fade-in on spawn
- 16 additional tests for spawn logic and enemy behavior

#### 6. HUD & match rules

- Health left, time center, score right
- Screen-reader announcements only for milestones: 30s, 10s, low health, match end
- Final 10s warning and low health alerts
- Match duration default: 120s; end by timer or death; score freezes on finish
- 1.5s finish sequence before emitting `onFinish(MatchResult)` snapshot with config + seed
- Interim result screen until final phase
- 5 new match-rule tests

#### 7. Main screens

- Visuals based on reference images: `ui_scene_background.png`, nine-slice panels, button styling from `ui_sheet`
- Menu: Play, Options, How to play, latest result, Ranking / Match history
- Record tabs with ARIA semantics and keyboard arrows
- Nickname modal on first play; validation for 3–16 chars
- Options screen for nickname and audio; duration/spawn tuning in phase 8
- Leave-battle confirmation while match is suspended
- Result screen with title, score, time, cause, “New best!” logic, and local storage of last result and config-specific record
- Touch controls + pause button deferred to phase 10

#### 8. Options

- Duration (60–180 s, step 10) and spawn interval (1–15 s, step 1, default 3)
- Steppers with `role=spinbutton`, disabled at limits
- Automatic save on change, reset to defaults, screen-reader announcement
- Input normalization via `normalizeOption`, preserving step alignment and defaulting invalid values
- Snapshot config via `createMatchConfig(options)`

#### Security deploy on Vercel (end of Day 1)

- `vercel.json`: Vite framework, `npm ci` + `npm run build` -> `dist`
- Cache rules for static assets and security headers
- Local production build validation via `vite preview`
- Production deploy performed by the user
- CSP checked in the production build with MSW and PixiJS

### Day 2

#### 9. Ranking & history

- Typed contracts + Axios client with timeout
- MSW handlers, fixtures, persisted in-memory DB works in production build
- TanStack Query pagination, cache, invalidation, retries, `placeholderData`
- Idempotent registration with client-generated match ID and persisted pending queue
- Late responses do not overwrite fresh data
- UI for scenario selection and reset

#### 10. Pause

- Manual pause (keyboard/button) and automatic pause (loss of focus / tab hidden)
- Resume requires explicit action; no accumulator/input buildup

#### 11. Playwright (critical flows first)

- Instrumentation with seed, controlled clock, and state readouts
- Options flow
- Match: movement, shooting, end-by-time/death, pause
- Ranking/history flows (empty, error, pagination, timeout without duplication, pending after refresh)
- Visual checks for menu, arena stability, results
- Desktop + mobile Chromium coverage, HTML report, traces on failure

#### 12. Final Vercel deployment

#### 13. Documentation

- `README.md`
- `ARCHITECTURE.md`

#### 14. Polish & performance

- Measure FPS, p95 frame time, and entity count in a 3-minute match

## Key decisions

- npm as package manager
- Player enters nickname on first match; `playerId` generated and stored locally
- Mobile only in landscape with a rotate reminder
- CSS only / CSS Modules + sprites from `ui_sheet`
- Vitest for pure game logic + Playwright for E2E
- Local Git; GitHub MCP will be authenticated manually later
- PixiJS controlled imperatively without `@pixi/react`
- XML ship atlas converted to Pixi JSON via `npm run assets:atlas`
- Vite bundle in `dist/static/` to avoid collisions with `public/assets/`
- SVG/SWF moved to `assets-src/vector` and excluded from deploy
- TypeScript 6 with `@types/web` instead of the DOM lib
